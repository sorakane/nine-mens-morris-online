# ゲーム状態と演出の分離

## 調査した既存構成

| 領域                     | 既存の責務                                                                    |
| ------------------------ | ----------------------------------------------------------------------------- |
| `lib/game.ts`            | 配置・移動・飛行・ミル・取得可否・勝敗を判定する純粋関数                      |
| `lib/room.ts`            | 対戦者と観戦者の権限、対局開始、双方同意の巻き戻し                            |
| `app/api/rooms/route.ts` | Cookie で本人確認、D1 の revision による単一の比較更新                        |
| `app/page.tsx`           | POST 応答と約 1.2 秒間隔の GET から確定した Room を反映。低い revision は破棄 |
| `app/globals.css`        | 盤面、手番案内、直前の移動経路・取得候補・ミルの表示                          |
| `components/music.tsx`   | この端末だけで鳴る BGM                                                        |

ゲームの判定関数、リクエスト形式、ポーリング間隔、権限、巻き戻しの単位は変更していません。
従来の盤面に直接付いた到着アニメーションは外し、直前の一手の静的な案内は残しました。

## 確定イベント

`lib/confirmed-events.ts` は既存の `changeRoom` 成功後に意味的な事実を添えます。
ミルの成否は既存の `game.capture` を使い、成立した交点だけを既存の `MILLS` から取得します。
取得イベントには確定した取得位置と取得前の駒の色を記録します。演出からルールを再判定しません。

イベントと盤面は同じ D1 JSON、同じ revision の比較更新で保存します。競合や不正操作はイベントも公開しません。
ID は `roomId:sequence`。sequence は巻き戻し・次の対局でも単調増加し、直近 32 件を保存します。
GET / POST 応答に `eventCursor`, `events`, `serverTime` を追加する互換的な拡張で、DB スキーマの変更はありません。
ミル直後に取得されても、次の GET には両方のイベントが残ります。

同期するのは「誰が・どこで・何をしたか」のみです。演出の強度、経過時間、表示段階、キュー、設定は送信しません。

## 端末内の Presentation

- `lib/presentation/events.ts`: 同期する意味的イベントの型。
- `lib/presentation/director.ts`: 重複除外、鮮度、再接続、短いキュー、演出レシピとローカル時計。
- `components/presentation/use-presentation.ts`: React 購読と端末設定、非表示・オフライン時の破棄。
- `components/presentation/presentation-stage.tsx`: 盤面の上に描く、クリックを遮らない表示層。
- `components/presentation/cut-in.tsx`: 斜め帯、MILL、プレイヤー名。
- `components/presentation/presentation.css`: カットイン、強調、取得する駒の視覚的コピー、フラッシュ。

`accept` は確定した Room を直ちに反映してから Presentation に通知します。
演出には盤面更新関数や通信関数を渡しません。手番判定・ボタンの操作可否も演出に依存しません。
ヒットストップはキーフレームの短い静止区間で、JavaScript や通信を停止しません。
取得された駒は正しい盤面では既に空欄です。その上の操作できないコピーだけが消えます。

ミルは 720ms（strong）、取得は 460ms（normal）。複数ミルや勝利する取得には finisher の強度が使えます。
勝利する取得は 560ms。最大 2 件の待機キューで、通常の次の一手・巻き戻し・次の対局が届けば古い演出を打ち切ります。
同じイベントを再受信しても、再生中・完了後・設定変更後とも再生しません。
全員が同じ確定イベントから同じレシピを選びますが、設定と受信時刻は端末ごとに異なります。
既存のポーリングを保っているため、全端末の演出開始が同じフレームになる保証はありません。

## 接続復帰とアクセシビリティ

最初の読み込み、部屋の変更、通信エラー後、タブ復帰、6 秒以上の受信間隔、履歴欠落時は、最新 cursor を基準にして過去を再生しません。
サーバー時刻で 5 秒より古いイベント、5 秒を超えたリクエストの応答からも演出を開始しません。
タイマーは破棄し、古いコールバックが走っても現在の演出を変更できない世代管理があります。

設定はスライド式スイッチで ON / OFF を切り替え、ON のときに「通常の演出」「控えめな演出」を選べます。
内部の full / reduced / off と localStorage に保存する端末設定は従来のままです。
OS が動きを減らす設定なら初期値は Reduced（Off を保存していた場合は維持）。
Reduced は揺れ・フラッシュ・速度線・吹き飛びを使わず穏やかな表示にします。
OS の軽減指定は CSS と揺れ処理でも尊重します。Off でも手番、ミルの線、取れる駒の枠と案内は表示します。
演出層は aria-hidden、pointer-events: none。読み上げには既存の手番・直前の一手を使い、情報を重複させません。

## 拡張と検証

将来の勝利・終盤・逆転などは、サーバー側で確定事実を追加し、イベント型・レシピ・対応表示を登録します。
normal / strong / finisher の強度はレシピが決めます。ゲーム側に演出待ちやアニメーション状態を追加しないでください。

`tests/confirmed-events.test.ts` と `tests/presentation.test.ts` は、ルールを変更しないイベント記録、連続イベント、重複、順序逆転、再接続、鮮度、設定、キュー、タイマー破棄を検証します。
`tests/events.integration.mjs` は専用の検証ルームを作り、実 API での競合、2 人と観戦者の同期、ミルと取得、相互同意の巻き戻しを検証します。
既存のゲーム・部屋・多人数観戦の検証も継続します。
